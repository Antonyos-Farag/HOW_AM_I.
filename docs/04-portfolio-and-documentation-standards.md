# 4. Technical Documentation Standards, Career Direction & Learning Methodology

## Portfolio & Technical Documentation Philosophy

I am developing a technical portfolio centered on practical learning, reproducible experiments, and clear documentation.

### Intended GitHub Portfolio Contents
- **TryHackMe Room Write-Ups:** Structured investigative write-ups and room walkthroughs.
- **Technical Walkthroughs & Investigation Notes:** Step-by-step documentation of forensic and incident investigations.
- **Security Analysis & Detection Experiments:** Telemetry generation, Sigma rule creation, and SIEM alert analysis.
- **Lab Configurations & Troubleshooting Notes:** Architecture deployment details and real-world troubleshooting steps.
- **Concept & Tool Breakdowns:** Explanations of the techniques, tools, parameters, and concepts used.
- **Technical Evidence:** Supporting screenshots, architecture diagrams, SIEM queries, and log artifacts.

### Documentation Standard
My goal is **not** simply to publish answers or flags. Every technical document or write-up should explain:
1. **The Investigation Process:** How the problem or incident was approached.
2. **The Reasoning Behind Each Step:** *Why* a specific hypothesis, query, or command was chosen.
3. **The Evidence Observed:** Exact log entries, packet captures, file-system artifacts, or system behaviors found.
4. **The Tools Used:** Commands, parameters, and how the tool parses or interacts with the underlying data.
5. **The Lessons Learned:** Key takeaways for detection, prevention, or deeper system understanding.

## Learning Style & Expectations

I prefer structured, technically accurate explanations that help me understand *why* something works, not just what commands to execute.

- **Valued:** Step-by-step explanations with practical examples; underlying logic, mathematics, or system behavior; clear explanations of commands, tools, parameters, and outputs; realistic lab exercises and troubleshooting; connections between theory and implementation; honest feedback on mistakes and knowledge gaps; structured roadmaps built on prerequisites.
- **Avoided:** Exaggerated claims, unnecessary motivational language, or superficial explanations that make a subject appear easier than it really is.
